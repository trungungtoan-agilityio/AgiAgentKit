# C6 — đáp án (chỉ cho người chấm)

Agent làm thẻ KHÔNG được đọc file này.

## Nguyên nhân gốc

Trong `src/library.ts`, `borrow` đẩy cùng một object `Loan` vào hai nơi: `this.loans` (sổ cái) và `this.watchList` (danh sách theo dõi mà `listOverdue` đọc). Hai nơi này đang dùng chung tham chiếu.

`settle` (gọi từ `returnBook`) có hai nhánh:

- Phí = 0 (trả đúng hạn): sửa trực tiếp object (`loan.returnedAt = now`). Vì dùng chung tham chiếu nên `watchList` cũng thấy loan đã đóng.
- Phí > 0 (trả trễ): tạo bản sao `{ ...loan, returnedAt, feeCents }` và thay vào `this.loans`. Object gốc trong `watchList` vẫn có `returnedAt === null`, nên `listOverdue` tiếp tục trả loan này như thể chưa trả.

Vì vậy lỗi chỉ xuất hiện với loan trả TRỄ rồi gọi `listOverdue` sau đó; loan trả đúng hạn không bao giờ bị. Đó là lý do triệu chứng "đôi khi".

## Tái hiện tối thiểu

```ts
const lib = new Library();
lib.addMember("m1", "A"); lib.addBook("b1", "B");
lib.borrow("b1", "m1", t0);                 // hạn = t0 + 14 ngày
lib.returnBook("b1", t0 + 16 ngày);          // trả trễ -> có phí -> sao chép
lib.listOverdue(t0 + 30 ngày);               // BUG: vẫn chứa loan của b1
```

## Cách sửa chấp nhận được

- Một nguồn sự thật: bỏ `watchList`, để `listOverdue` đọc từ `this.loans`; hoặc
- `settle` luôn sửa tại chỗ (không sao chép), hoặc cập nhật cả `watchList`.

Không chấp nhận: chỉ thêm bộ lọc ở `listOverdue` kiểu "loại loan có `feeCents` > 0" hay đối chiếu id với `this.loans` mà vẫn giữ hai bản sao dữ liệu (vá triệu chứng).
